# 🌌 천문학 전문가 챗봇 (Astronomy Expert Chatbot)

> LangChain · Groq LLM · Gradio 를 활용한 첫 번째 LLM 애플리케이션 토이 프로젝트

역할(Role)을 부여받은 LLM에게 질문을 던지고 답변을 받는 간단한 웹 챗봇입니다.
"당신은 천문학 전문가입니다"라는 시스템 프롬프트를 통해 특정 도메인에 특화된 답변을 생성합니다.

## 📖 프로젝트 소개

LLM 애플리케이션 개발의 기본 구조를 익히기 위해 만든 첫 번째 프로젝트입니다.
사용자의 질문을 받아, **시스템 프롬프트로 역할이 고정된 LLM**이 답변을 생성하고,
그 결과를 웹 UI로 보여주는 전체 파이프라인을 직접 구현했습니다.

- **역할 부여(Role Prompting)**: `system` 메시지로 LLM에게 "천문학 전문가"라는 페르소나를 설정
- **입력 → 처리 → 출력**의 표준 LLM 체인 구조를 LangChain으로 구성
- **Gradio**로 코드 몇 줄만에 웹 인터페이스 제공

## 🎯 주요 기능

- 시스템 프롬프트로 LLM의 역할(페르소나) 고정 — 답변 톤/전문성 제어
- 사용자 질문 입력 시 실시간 답변 생성
- 웹 브라우저에서 바로 사용 가능한 GUI 제공 (터미널 `input()` → Gradio 전환)

## 🛠 기술 스택

| 구분        | 사용 기술                | 선택 이유                                                                          |
| ----------- | ------------------------ | ---------------------------------------------------------------------------------- |
| LLM         | **Groq (Llama 3.3 70B)** | OpenAI API 무료 크레딧 소진으로 전환 · Groq은 무료 티어 제공 + 추론 속도 매우 빠름 |
| 프레임워크  | **LangChain**            | 프롬프트–모델–파서를 체인으로 표준화, 모델 교체가 자유로움                         |
| UI          | **Gradio**               | 최소 코드로 웹 데모 제작 가능                                                      |
| 패키지 관리 | **Poetry**               | 의존성/가상환경 통합 관리, 재현 가능한 환경 보장                                   |

> 💡 **OpenAI → Groq 전환 배경**
> 초기에는 OpenAI API로 개발했으나 무료 사용 한도(크레딧)가 부족해 유료 결제가 필요했습니다.
> **Groq**은 무료 API 티어를 제공하고 오픈소스 모델(Llama 등)을 매우 빠른 속도로 서빙하기 때문에
> 학습·토이 프로젝트 목적에 적합하다고 판단해 전환했습니다.
> LangChain을 사용한 덕분에 코드 대부분을 그대로 두고 `ChatOpenAI` → `ChatGroq` 한 줄만 교체하면 되었습니다.

## 🔗 LLM 호출 흐름 (LangChain Chain)

LangChain의 **LCEL(LangChain Expression Language)** `|` 파이프 문법으로 세 컴포넌트를 연결했습니다.

```
┌──────────────────┐   프롬프트 문자열 생성   ┌──────────────┐   AI 메시지 객체 반환   ┌──────────────────┐
│  PromptTemplate  │ ──────────────────────▶ │  LLM (Groq)  │ ──────────────────────▶ │  OutputParser    │ ──▶ 최종 문자열
│  (역할 + 질문)    │                          │  Llama 3.3   │                          │  (문자열만 추출)  │
└──────────────────┘                          └──────────────┘                          └──────────────────┘
```

```python
chain = prompt | llm | output_parser
```

| 단계 | 컴포넌트             | 역할                                | 입력 → 출력                        |
| ---- | -------------------- | ----------------------------------- | ---------------------------------- |
| 1    | `ChatPromptTemplate` | system(역할 설정) + user(질문) 조합 | 사용자 질문 → **완성된 프롬프트**  |
| 2    | `ChatGroq`           | LLM 추론                            | 프롬프트 → **AIMessage 객체**      |
| 3    | `StrOutputParser`    | 응답 후처리                         | AIMessage → **순수 텍스트 문자열** |

> `system` 메시지는 LLM에게 역할을 부여하는 부분입니다.
> `"당신은 천문학 전문가입니다"` 뒤에 `"답변은 3문장 이내로 간결하게"` 같은 **출력 형식 요구사항을 추가**하면
> 원하는 스타일의 답변을 얻을 수 있습니다.

## 🦜 왜 LangChain을 썼나?

LangChain 없이도 각 LLM SDK를 직접 호출할 수 있지만, 다음과 같은 이점 때문에 사용했습니다.

- **표준화된 체인 구조**: `프롬프트 | 모델 | 파서`처럼 파이프라인을 선언적으로 구성 → 코드 가독성 ↑
- **모델 교체 자유도**: `ChatOpenAI` ↔ `ChatGroq` 한 줄만 바꿔도 나머지 코드 재사용 (이번 프로젝트에서 실제 체감)
- **출력 파싱 자동화**: `StrOutputParser` 등으로 응답 후처리를 표준 컴포넌트로 처리
- **확장성**: 이후 프로젝트에서 RAG, 메모리, 도구 호출(Agent) 등으로 자연스럽게 확장 가능

즉, 단순 프로젝트에선 차이가 작아 보여도 **규모가 커질수록 유지보수와 확장에서 큰 차이**가 납니다.

## 📦 왜 Poetry를 썼나?

`pip + requirements.txt` 대신 **Poetry**를 사용했습니다.

- **의존성 + 가상환경 통합 관리**: 별도로 `venv`를 만들 필요 없이 `poetry`가 격리 환경까지 관리
- **재현 가능한 환경**: `poetry.lock` 파일이 정확한 버전을 고정 → 다른 PC/협업자도 동일한 환경 재현
- **명확한 의존성 분리**: 개발용/운영용 패키지를 구분해서 관리 가능

## 💡 좋은 프롬프트 작성 팁 (Prompt Engineering)

모델에게 정확한 지시를 제공하고 원하는 출력을 얻기 위해 입력을 최적화하는 기술입니다.

### 1) 구체적이고 명확하게 지시하기

- 프롬프트는 명확하고 간결하게, 불필요한 정보를 줄이고 **핵심 요구사항에 집중**합니다.
- 원하는 출력이 무엇인지 정확히 알려줍니다.

```python
# ❌ 애매한 지시
llm.invoke("GPT-3.5 모델의 파라미터 개수는 몇개인가요?")

# ✅ 출력 형식을 명확히 지정 (LLM은 한글+숫자 표현에 약해 오류가 잦음 → 영어로 질문하면 더 안정적)
llm.invoke("How many parameters does the GPT-3.5 model have? Please answer using only Arabic numerals.")

# ✅ 구분자(' ')로 대상을 명확히, '모두'처럼 애매한 표현 대신 '3개'처럼 구체적으로
llm.invoke("'행복'을 뜻하는 영어 단어를 3개 찾아주세요.")
```

### 2) 참고 예시 제공하기 (Few-shot)

원하는 출력 형식/스타일을 예시로 보여주면 모델이 방향을 잘 잡습니다.
(예시 0개 = zero-shot / 1개 = one-shot / 여러 개 = few-shot)

```python
llm.invoke(
    """다음 예시와 같이 제시된 뉴스에서 3개의 키워드를 추출하세요:
    <예시>
    뉴스: 정부는 의과대학 입학 정원을 2000명 증가시킬 계획의 세부사항을 이달 20일에 공개할 예정이다...
    키워드: 의대, 정원, 확대
    </예시>

    뉴스: 삼성전자가 내년 초에 자체 개발한 AI 가속기를 처음으로 출시할 예정이다...
    키워드:
    """
)
```

### 3) 단계별로 생각하게 유도하기 (Chain-of-Thought)

복잡한 문제는 단계별로 분해하도록 유도합니다. 질문 마지막에 **"Let's think step by step"** 같은 문구를 추가하면
모델이 순차적으로 추론해 정답률이 올라갑니다.

## 📚 배운 점 & 회고

- LLM 애플리케이션의 **기본 파이프라인(프롬프트 → 모델 → 파서)** 구조를 이해했다.
- LangChain 덕분에 **모델 교체가 얼마나 쉬운지** 직접 경험했다 (OpenAI → Groq).
- **시스템 프롬프트(역할 부여)**와 **프롬프트 엔지니어링**이 답변 품질에 큰 영향을 준다는 걸 확인했다.
